# Совёнок

Интерактивный обход шахматной доски на HTML, CSS и JavaScript. Сборка — Vite; UI-фреймворков и серверной части нет.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

```sh
npm install
npm run dev
```

Открыть адрес, который выведет Vite. `npm run build` создаёт статическую версию в `dist/`, `npm run preview` запускает её локально. Открывать исходный `index.html` через `file://` не нужно: приложение использует ES-модули и Web Worker.

## Соотношение и размеры

Сначала задайте коэффициенты **H₀ : D₀ : V₀**: по горизонтали, по диагонали и по вертикали. Допустимы неотрицательные целые числа, но не три нуля. Коэффициенты используются как введены: они не сокращаются на общий делитель. Множитель x — положительное целое, поэтому доска 1 × 1 не участвует в подборе.

После заполнения трёх полей автоматически выбирается минимальный найденный обход в пределах **1–50 клетки на сторону**, включая чётные размеры. Сначала сравнивается площадь, затем меньшая сторона, затем ширина. Например, для 2 : 1 : 2 при площади 16 выбирается 2 × 8, а не 4 × 4.

- При ручном вводе ширины выбирается минимальная найденная высота для этой ширины; при вводе высоты — минимальная ширина.
- Горизонтальный бегунок перебирает только проверенные ширины при текущей высоте. Вертикальный — только проверенные высоты при текущей ширине. Их позиции — индексы допустимых значений, поэтому числа могут изменяться с пропусками.
- В списке «Проверенные размеры» доступны все найденные варианты для текущего соотношения.
- Для нулевых коэффициентов поддерживаются, в частности, прямые обходы 1 × b и a × 1. Одними диагональными ходами посетить клетки обоих цветов нельзя.

## Математическая проверка

Пусть a — число столбцов, b — число строк. Клетки — вершины пути; один ход ведёт в соседнюю клетку, в том числе по диагонали. Начало — снизу слева (0, 0), конец — сверху справа (a − 1, b − 1). Пересечение линий между клетками разрешено, повторное посещение клетки — нет.

Для S = H₀ + D₀ + V₀ проверяем:

1. a, b — положительные целые; a × b > 1.
2. x = (a × b − 1) / S — положительное целое.
3. H = H₀x, D = D₀x, V = V₀x; H + D ≥ a − 1, V + D ≥ b − 1.
4. **(H + D) mod 2 = (a − 1) mod 2** и **(V + D) mod 2 = (b − 1) mod 2**.
5. (H + V) mod 2 = (a + b − 2) mod 2: 0 для одноцветных углов, 1 для разноцветных. Эта проверка следует из двух предыдущих, но оставлена явно.
6. При нечётном b необходимо H ≥ a − 1; при нечётном a необходимо V ≥ b − 1. Ограничения следуют из раскраски строк/столбцов по чётности и разности степеней вершин пути. Для чётной соответствующей стороны эти нижние границы не применяются.
7. Число ходов каждого типа не превосходит числа различных соседних пар этого типа; для посещения обоих цветов нужны ортогональные переходы.

В условии чётности важно расстояние, а не количество столбцов: при чётном a расстояние a − 1 нечётное, поэтому H + D должно быть **нечётным**. Аналогично для строк. Из формул следует, что D нечётно только при двух чётных сторонах; в остальных случаях D чётно.

Эти условия **необходимы, но недостаточны**. Контрпример: 3 × 3, H = 4, D = 0, V = 4. Все проверки проходят, но полный перебор показывает, что ортогональный обход между указанными углами имеет только квоты (H, V) = (2, 6) или (6, 2). Независимый перебор маленьких досок входит в тесты; он также проверяет, что арифметические фильтры не отбрасывают реально существующие маршруты.

## Разрешённые блоки

`solver.js` собирает маршрут из HVHV, HDHD, VDVD, переходов HH, шнуровки и прямого завершающего прохода. Сначала расходуются лишние горизонтали через HVHV/HDHD, затем VDVD, после обычных полос — шнуровка. Произвольный поиск путей внутри полос не используется.

Для чётной высоты последние две строки полосы закрываются одним из блоков:

- **VDVH**: (0,0) → (0,1) → (1,0) → (1,1) → (2,1).
- **HDHH**: (0,0) → (1,0) → (0,1) → (1,1) → (2,1).

Последний ход входит в соседнюю полосу; если достигнут финиш, этот переход за границу доски не выполняется. Для чётной ширины одиночного последнего столбца нет: нужное число проходных полос обеспечивает конец сверху справа.

Вертикальная шнуровка — чередующийся диагональный подъём, вертикальный подъём, горизонтальный переход, вертикальный спуск и диагональный спуск по оставшимся клеткам. Вертикальные участки могут быть пустыми. Её горизонтальная копия **DDHHVHHDDV** получается транспонированием. Генератор пробует обе ориентации с обменом внутренних H/V-квот и возвращает путь в исходные координаты. Физические квоты при этом сохраняются.

Расчёт и подбор размеров выполняются в `src/solver.worker.js`. Каждый найденный путь независимо проверяется: все клетки посещены, повторов и прыжков нет, концы правильные, квоты точные.

**Конструктор блоков не является полным решателем общей задачи.** В интерфейсе доступны только размеры с построенным и проверенным маршрутом; «минимальный найденный» означает минимум среди них в диапазоне до 50 × 50. Если какие-то размеры прошли арифметику, но конструктор их не решил, интерфейс сообщает их количество. Отказ конструкции не выдаётся за доказательство невозможности.

## Проверка

```sh
npm test
npm run build
```

Тесты проверяют чётность относительно расстояния, нулевые и ошибочные коэффициенты, x ≥ 1, все допустимые размеры для соотношения 1 : 2 : 4 до 50 × 50, новые блоки и их порядок, разные соотношения, транспонирование, минимальную площадь и tie-break, прямые обходы, независимый полный перебор маленьких досок и обнаружение неверных маршрутов.

Vite выбран по [официальной документации](https://vite.dev/guide/). Транзитивная dev-зависимость `source-map-js` обновлена до 1.2.2 с исправлением GHSA-68fv-2mgg-jv7q. Повторная проверка `npm audit` 16.10.2026 не обнаружила уязвимостей.

## GitHub Pages

Сайт: https://alexeykupershtokh.github.io/sovenok/.

В `.npmrc` закреплён публичный реестр `https://registry.npmjs.org/`, чтобы установка не зависела от локального npm-окружения.

Каждый push в `main` запускает `.github/workflows/deploy.yml`: установка через `npm ci`, тесты, сборка и публикация `dist` в GitHub Pages. Workflow также можно запустить вручную в GitHub Actions.

В `vite.config.js` задан `base: "./"`: HTML, CSS, favicon и Web Worker используют относительные пути и работают как в корне локального сервера, так и в `/sovenok/` на Pages. В репозиторий отправляются исходники и lock-файл; `node_modules` и `dist` исключены.
