# Совёнок

Интерактивный обход шахматной доски на HTML, CSS и JavaScript. Сборка — Vite; UI-фреймворков и серверной части нет.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

```sh
npm install
npm run dev
```

Открыть адрес, который выведет Vite. `npm run build` создаёт статическую версию в `dist/`, `npm run preview` запускает её локально. Открывать исходный `index.html` через `file://` не нужно: приложение использует ES-модули и Web Worker.

## Условия

- M — столбцы, N — строки. Оба размера нечётные, от 1 до 31.
- Клетки — вершины пути; один ход ведёт в соседнюю клетку, в том числе по диагонали. Пересечение линий между клетками допустимо.
- Начало — снизу слева, конец — сверху справа. Каждая клетка посещается ровно один раз.
- Число переходов равно **M × N − 1**. По согласованной поправке именно оно должно делиться на 7.
- При `x = (M × N − 1) / 7` нужны ровно `H = x`, `V = 4x`, `D = 2x` ходов.
- Проверяются положительные целые размеры, нечётность, делимость, цвет углов и необходимые ограничения `H ≥ M − 1`, `V ≥ N − 1`.

Последние ограничения следуют из раскраски строк и столбцов по чётности. Например, в раскраске строк число горизонтальных рёбер на чётных строках минус число таких рёбер на нечётных строках равно M − 1. Поэтому всего горизонтальных ходов должно быть хотя бы M − 1. При разрешённых нечётных M и N углы всегда одного цвета, а общее число ходов чётно; диагональных ходов тоже чётное число.

## Построение и проверка

`solver.js` собирает маршрут строго из блоков HVHV, HDHD, VDVD, переходов HH, возвратной шнуровки и завершающего прямого прохода. Сначала расходуются лишние горизонтали через HVHV/HDHD (выбор зависит от остатка V/D), затем идут VDVD, после обычных полос — шнуровка. Количество блоков вычисляется из квот; произвольные пути внутри полос не перебираются. Возвратная полоса состоит из диагонального подъёма с чередованием сторон, вертикального подъёма, одного горизонтального перехода, такого же вертикального спуска и диагонального спуска по оставшимся клеткам. Вертикальные части могут быть пустыми.

Если N > M, первым выполняется виртуальное транспонирование: размеры и квоты H/V меняются местами внутри расчёта. Координаты готового пути возвращаются обратно; отображаемая доска, её начало/конец и физические квоты 1:4:2 сохраняются. В этой ориентации полосы идут по строкам, последний прямой проход — по верхней строке вправо. Интерфейс помечает такое решение словом «транспонировано». Если эта конструкция не подходит по квотам (например, для 9 × 11), используется исходная ориентация с завершающим подъёмом по правому столбцу.

В `src/solver.worker.js` расчёт выполняется отдельно от интерфейса. Каждый найденный результат независимо проверяется: все клетки на месте, повторов и прыжков нет, концы правильные, количества ходов точные. Номера на доске означают порядок посещения; стрелки, ползунок и кнопка воспроизведения позволяют пройти путь по шагам.

Построение ограничено 2,5 секунды. **Оно не является полным решателем общей задачи.** Если полосы не дали решения или закончилось время, интерфейс сообщает «маршрут пока не найден», а не утверждает невозможность. Для 3 × 19 транспонирование теперь даёт маршрут, хотя конструкция с последним вертикальным столбцом его не давала.

Для 1 × 1 путь состоит из единственной клетки, число ходов каждого типа равно нулю.

## Проверка

```sh
npm test
npm run build
```

Тесты проверяют ограничения, полные маршруты с точными квотами, разрешённые блоки и их порядок, транспонирование с сохранением физических квот, завершающий столбец или строку, отказ без ложного утверждения о невозможности и обнаружение ошибочных маршрутов. Примеры: 3 × 5, 5 × 17, 9 × 11, 11 × 9, 15 × 15, 3 × 19.

Vite выбран по [официальной документации](https://vite.dev/guide/). При установке Vite 8.3.0 `npm audit` сообщает об advisory GHSA-68fv-2mgg-jv7q в его транзитивной dev-зависимости `source-map-js@1.2.1`. Исправленная версия 1.2.2 на момент установки отсутствует в npm; принудительный откат Vite до старой основной версии не применялся. Эта зависимость не входит в статическую сборку приложения.

## GitHub Pages

Сайт: https://alexeykupershtokh.github.io/sovenok/.

Каждый push в `main` запускает `.github/workflows/deploy.yml`: установка через `npm ci`, тесты, сборка и публикация `dist` в GitHub Pages. Workflow также можно запустить вручную в GitHub Actions.

В `vite.config.js` задан `base: "./"`: HTML, CSS, favicon и Web Worker используют относительные пути и работают как в корне локального сервера, так и в `/sovenok/` на Pages. В репозиторий отправляются исходники и lock-файл; `node_modules` и `dist` исключены.
